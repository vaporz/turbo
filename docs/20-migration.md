# 版本与行为变更

这篇是升级前必读：**每个版本改了什么行为、你会看到什么不同、需要做什么**。

Turbo 的约定是：**行为变更不提供兼容开关**。旧行为如果是个坑，就直接改掉并在下面写清楚，
由使用方自己回归——所以升级前请对照本文的清单过一遍自己的服务。

## 1. 版本时间线

| 版本 | 提交 | 主题 |
|---|---|---|
| v0.6.0 | `b017edc` | 绑定/错误语义/热重载/代码生成的一批修复；最低 Go 提到 1.27.1 |
| v0.6.1 | `16fff6f` | 修：全局拦截器活不过一次热重载 |
| v0.6.2 | `091a5ea` | 修：热重载读到半写/空配置、重载重建无锁；错误消息不再回显请求内容；新增 `config.log_level`；路由审计分级 |

更早的 v0.5.x 与本文档描述的行为有明显差异（组件路径语法、错误码、绑定优先级、thrift JSON 等），
如果你还在 v0.5.x，请按 v0.6.0 的清单一次性升级。

## 2. v0.6.0：绑定、错误、热重载、代码生成

### 2.1 必读的行为变更

| 变更 | 说明 | 你会看到什么不同 |
|---|---|---|
| **绑定优先级明确为 injected > path > body > query/form** | 服务端通过 `turbo.InjectParam` 注入的值**不再被请求覆盖**；JSON 请求也不再忽略 URL 参数 | 原来"客户端能从 body/query 盖掉注入值"的用法会失效；JSON 接口多出了 path/query 的取值能力 |
| **路径参数不再输给 query** | query 里与路由变量同名的参数不再覆盖路径值；参数名拼写归一改成宽口径 | `?yourName=`、`?your_name=` 现在都能绑上同一个字段 |
| **"存在但非法"的参数明确拒绝** | 标量非法 → 400（原来 200 + 零值）；列表里有非法元素 → 400（原来 200 + 整个列表被丢掉） | 客户端会开始收到 400，而不是"成功但字段是 0" |
| **错误状态码语义** | 请求 body 无法解析：500 → **400**；其它失败仍是 500；可用 `turbo.Errorf(status, …)` / `WithStatus` 自带状态码 | 监控里 4xx 会变多、5xx 变少；响应体格式不变 |
| **拦截器改为链式执行** | 全局拦截器（`SetCommonInterceptor`）**对所有路由执行**，排在路由级拦截器之前 | 原来"路由级一写、全局就不跑"的隐式行为消失；全局拦截器里的副作用（计数/审计/限流）需自己保证幂等 |
| **组件声明的路径改为显式匹配** | `/hello` 只匹配自身；`/hello/{name}` 恰好一段；`/hello/*` 匹配自身及以下；`/*` 匹配全部；`"/"` **不再**是通配，只匹配根 | 旧配置里用 `"/"` 或尾斜杠表达"前缀"的写法会失效（这是有意的，见下） |
| **Thrift 的 JSON body 按键名对应参数** | body 形如 `{"request":{…}}`；未知键从"忽略"改为 **400**；多参数方法从"连接断开"变为可用 | thrift JSON 调用方需要按参数名包裹 |
| **最低 Go 版本 1.27.1** | `go.mod` 的 `go` 指令即最低工具链要求；离线构建机上要么预装 Go 1.27.1，要么 `GOTOOLCHAIN=local` | 构建机需要新工具链 |

> **为什么 `/` 不再是通配**：旧规则下 `- GET / X` 会让这个拦截器变成全局的，而"读配置"的人无法从那一行
> 看出这一点；尾斜杠也有同样的"静默变宽"问题。新规则要求显式写 `/*`。

### 2.2 新增能力（v0.6.0）

- 错误可带自己的 HTTP 状态码：`turbo.Errorf(status, …)` / `turbo.WithStatus` / `turbo.StatusOf`；
- **启动路由审计**：缺鉴权拦截器的配置被拒绝（`auth.interceptors` / `auth.public_routes`，
  见 [16-auth-and-route-audit.md](16-auth-and-route-audit.md)）；
- 启动打印路由表、404 不再静默（`route:` 行与 `404 no route for …` 日志）；
- 配置键 `json_field_names: proto|camel`（默认 `proto`，行为不变）；
- 日志排序工具 `turbo.SortKeysFirst` / `CheckSortingFunc`（用 logrus 的 `SortingFunc` 时不会丢字段）；
- 生成产物**可复现**（同一输入逐字一致）且**原子写**（生成失败不会留下半个文件）；
- `make tidy` / `make clean-gen` / `make vuln`（仓库自身的开发命令）。

## 3. v0.6.1：全局拦截器活过重载

| 变更 | 说明 |
|---|---|
| **修**：`SetCommonInterceptor` 装的全局拦截器，在一次成功的配置热重载之后会**静默失效** | 现在重建组件时会带上全局拦截器 |
| 连带修复 | 路由审计以前读到的全局拦截器列表恒为空，用全局鉴权拦截器时会把每条路由误判为 `UNPROTECTED`，导致启动被拒（假阳性） |

> **如果你用全局拦截器做鉴权，这一版必须升**：否则一次热重载就能把鉴权静默关掉。

## 4. v0.6.2：热重载的两个坑、错误消息、日志

### 4.1 修复

| 变更 | 说明 | 你会看到什么不同 |
|---|---|---|
| **读到空/半写配置会把整张路由表清空** | 就地写配置时，文件变更通知先报告"截断"，读到空文件后 Turbo 会把它当成"0 条路由的合法配置"装上去，于是全站 404 且进程看起来正常。现在：**拒绝没有任何路由的配置** + **读文件前先等它稳定**（v0.6.2 起） | 半写/空配置只会让这次重载失败并保留旧配置；日志里会出现 `urlmapping is empty…` |
| **热重载的重建读共享状态时没有加锁** | 重建组件与路由表的过程要读配置与已注册组件，而这两者在服务运行期间会被替换，因此既是数据竞争，也可能读到"半新半旧"的路由表。现在重建与替换整个在写锁内完成 | 无行为变化，只是修掉了竞态；重载期间新请求最多多等一次重建的时间 |
| **错误消息回显请求内容** | 绑定/解析失败的文本既返回给调用者、也写进日志：原来 body 会被整体回显、参数值会被引用、超范围数字会被回显。现在 body 只报字节数、参数值写成 `<redacted>`、被回显的数字也抹掉，**字段名与原因保留**（v0.6.2 起） | 400 响应里的 `msg` 文本变了（不含请求内容）；如果客户端解析过这段文本，需要跟着调整 |
| **路由审计的逐条裁决从 `info` 降到 `debug`** | 同时新增一行 `info` 汇总：`route audit: N route(s), N authenticated, N public, N unprotected`（v0.6.2 起） | `info` 级别下不再每条路由一行；`UNPROTECTED` 仍是 error，重叠声明与"无法核对"仍是 warning |

### 4.2 新增能力

`config.log_level`：给 Turbo 自己的日志指定级别（`panic` / `fatal` / `error` / `warn` / `info` /
`debug` / `trace`）。不配置则保持原样（`environment: production` 时为 `info`，其它情况为 `debug`）；
它只决定级别，格式与输出仍由 `environment` 决定；取值非法会在加载配置时被拒绝；与端口一样**需要重启**
（不参与热重载）。它放在 `config:` 段下，与**服务自己**的顶层 `log_level` 互不影响。

### 4.3 v0.6.2 升级检查表

- [ ] 生产配置里如果有"临时把 `urlmapping` 清空"这种操作，注意它现在会被拒绝（这是有意的）；
- [ ] 客户端/前端如果解析过错误响应里的 `msg`，确认能接受不含请求内容的新文本；
- [ ] 依赖"改配置后 0ms 生效"的自动化流程：重载现在最多晚约 100ms 生效；
- [ ] 想在 `info` 级别下安静一点，可以加 `config.log_level: info`（去掉逐条审计，保留汇总与运维行）；
- [ ] 用全局拦截器做鉴权的服务，确认已经在 v0.6.1 及以上（见第 3 节）。

## 5. 依赖与工具链

- **最低 Go 版本**：1.27.1（`go.mod` 的 `go` 指令）。构建机 Go 版本更低时会尝试**下载**工具链，
  离线环境必然失败，因此要么预装 Go 1.27.1，要么 `GOTOOLCHAIN=local` 并保证本机工具链足够新。
- **gRPC / Thrift 版本由使用方决定**：Turbo 只在自己的 `go.mod` 里声明依赖，你的服务用哪个版本由你的
  `go.mod` 决定（升级 turbo 不会强制升级你线上的 grpc/thrift）。
- **代码生成需要 legacy `protoc-gen-go` 排在 PATH 最前**，见
  [12-code-generation.md](12-code-generation.md)。
- **`make vuln`** 需要 govulncheck v1.8.0 或更新（更早的版本自带旧 `x/tools`，读不了 Go 1.27 的标准库）。

## 6. 已知限制（未修，升级前请知情）

- `google.golang.org/grpc` 的若干已知漏洞随其自身版本走；Turbo 不做方法名鉴权，其中"按完整方法名鉴权
  被绕过"那条对本项目不适用，但"能直连 gRPC 端口"的场景仍需自行评估网络暴露面；
- `github.com/apache/thrift` 的 `TFramedTransport` 相关告警在 Turbo 的运行时链路里不可达
  （服务端用 `TMultiplexedProcessor` + `TTransportFactory`，客户端用 `NewTSocket`）。
